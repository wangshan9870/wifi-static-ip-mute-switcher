# Wi-Fi 固定 IP 与静音切换器
Native macOS menu-bar app. Settings bind one home network, identified by the Wi-Fi (en0) gateway's MAC address, and a fixed IPv4 address; other known networks use DHCP. SSIDs are not used: macOS redacts them without Location Services, and the app needs no location permission. Public builds start with no router or IP; a user must configure both before networking or speaker automation runs.

Sources contains Swift app and pure policy. Resources contains the narrowly scoped privileged helper and installer. Tests exercises policy without changing networking. Build with ./build.sh; test with ./test.sh. Output goes in build/ (disposable). No credentials, network history, or location coordinates are recorded; only the bound home router MAC is stored. Keep an unknown network (disconnected, or gateway MAC not resolved) distinct from another network.

SettingsUI.swift implements the native AppKit window and forwards actions to AppDelegate, using the same handlers as the menu bar. It owns no polling or networking. Release its controls on window close, preserve unsaved text during status refresh, and display actual state instead of simulated success. Run ./test-ui.sh on macOS to check view states and window release without changing network or audio settings. The HTML in prototype/ is a design reference with simulated data only.

The sudoers rule permits only the literal `home` and `dhcp` helper operations. Changing the fixed IP requires macOS administrator authorization; the installer validates and writes a root-owned single-line address file. The helper reads that file as data, never sources it, validates it again, and accepts no additional arguments. Router binding changes need no privilege. The helper address file must exist and match the saved IP before applying home mode. Do not broaden sudo permissions or add arbitrary privileged operations.

Speaker protection is independent of IP automation and defaults on. The bound home router permits user-controlled sound; an unknown network mutes speakers without changing IP policy. CoreAudio targets built-in transport with the internal-speaker data source, including inactive speakers. Never mute headphones/external devices or change output selection. After two consecutive home observations, unmute internal speakers once and retry on failure. Do not override subsequent manual mute at home; leaving or an unknown network rearms home restoration. Startup at home also restores sound.

Detection is event-driven, not polled: SystemConfiguration notifications for en0 link/IPv4 and service IPv4 (gateway) changes, CoreAudio notifications for device list and built-in mute/data-source changes, plus wake. A second read 2 s after a new observation provides the two consecutive observations. Timers only confirm, retry with backoff after failures, or run a 5-minute safety check. Report errors and retry.
