# Wi-Fi 固定 IP 与静音切换器
Native macOS menu-bar app. Settings choose one exact home Wi-Fi SSID and a fixed IPv4 address; other known networks use DHCP. Public builds start with no SSID or IP; a user must configure both before networking or speaker automation runs.

Sources contains Swift app and pure policy. Resources contains the narrowly scoped privileged helper and installer. Tests exercises policy without changing networking. Build with ./build.sh; test with ./test.sh. Output goes in build/ (disposable). No credentials, SSID history, or location coordinates are recorded. Keep unknown SSID distinct from another network.

The sudoers rule permits only the literal `home` and `dhcp` helper operations. Changing the fixed IP requires macOS administrator authorization; the installer validates and writes a root-owned single-line address file. The helper reads that file as data, never sources it, validates it again, and accepts no additional arguments. SSID changes need no privilege. The helper address file must exist and match the saved IP before applying home mode. Do not broaden sudo permissions or add arbitrary privileged operations.

Speaker protection is independent of IP automation and defaults on. The exact configured home SSID permits user-controlled sound; unknown SSID mutes speakers without changing IP policy. CoreAudio targets built-in transport with the internal-speaker data source, including inactive speakers. Never mute headphones/external devices or change output selection. After two consecutive home observations, unmute internal speakers once and retry on failure. Do not override subsequent manual mute at home; leaving or unknown SSID rearms home restoration. Startup at home also restores sound. Poll every second and on wake; report errors and retry.
